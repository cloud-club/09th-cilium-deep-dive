## 01. eBPF (extended Berkeley Packet Filter)?
- 커널 내부에 존재하는 샌드박스 환경의 가상 머신에서 실행되는 이벤트 기반 프로그램
	- 커널 내부
		- Ring 0 권한 레벨로 실행됩니다. (모든 메모리/하드웨어 자원 접근 가능)
			- #참고 Ring 3 (가장 낮은 권한)
				- 일반 사용자 프로그램 실행
				- 커널 메모리 직접 접근 불가능
	- 샌드박스 환경의 가상 머신
		- Verifier를 통해 eBPF 프로그램이 커널을 손상시키거나 시스템을 멈추게 하는 것을 불가능하게 합니다.
	- 이벤트 기반 프로그램
		- eBPF는 이벤트 기반으로 동작하고, 커널 또는 애플리케이션이 특정 hook 지점을 지나갈 때 실행된다. 
			- hook 종류는 System Call, 함수 시작/종료, 커널 tracepoint, 네트워크 이벤트 등 여러가지가 포함될 수 있다.
		- 따라서, 평소레는 아무런 부하를 주지 않는다.

## 02. eBPF 프로그램 동작 흐름
![[Pasted image 20260412192459.png]]
1. 컴파일러가 소스 코드를 BPF 바이트 코드로 변환한다.
2. Userspace의 Loader가 `bfp()` 시스템콜을 통해 바이트 코드를 커널로 전달한다.
3. ==커널의 Verifier가 전달받은 eBPF 바이트 코드를 분석하여 실행되도 안전한 지 검증한다.==
4. 검증을 통과하면 JIT(Just-In-Time) 컴파일러가 eBPF 바이트코드를 현재 시스템의 CPU가 직접 실행할 수 있는 기계어 코드로 변환한다.
5. 변환된 코드를 지정된 hook에 연결한다.
6. 해당 이벤트 hook이 발생하면, 연결된 기계어 코드가 커널 내에서 직접 실행된다.


## 03. eBPF 핵심 구성 요소
- ### Verifier
	- eBPF의 문지기
	- 주요 검사 목록
		- 프로그램이 무한 루프에 빠지진 않는가?
		- 적절한 메모리에만 접근하는가?
			- 초기화되지 않은 변수나 레지스터를 읽으려고 하는가?
			- 허용된 메모리 외 임의의 커널 메모리에 접근하려고 하는가?
		- 허가된 기능만 호출하는가?
![[Pasted image 20260412192907.png]]


- ### Maps
	- eBPF의 두뇌
	- 데이터의 저장과 통신을 담당
	- 커널 내부에 존재하는 고성능 Key-Value 저장소
	- 해시 테이블, 배열, 스택, 큐, 링 버퍼 등 용도에 맞는 다양한 맵 타입 존재.
	- 데이터 흐름
		- 1) Kernel space -> User space
			- eBPF 프로그램이 수집한 데이터(메트릭, 이벤트 로그 등)을 맵에 저장하면, 사용자 애플리케이션이 이를 읽어와 시각화하거나 분석한다.
		- 2) User space -> Kernel space
			- 유저 스페이스에서 정책(차단 IP 목록 등)을 맵에 써놓으면, eBPF 프로그램이 이를 읽어와 실시간으로 정책을 적용한다.
		- 3) eBPF 프로그램 <-> eBPF 프로그램
			- 한 eBPF 프로그램이 맵에 특정 정보를 저장하면, 다른 eBPF 프로그램이 해당 정보를 읽어와 후속 처리를 한다.
![[Pasted image 20260412192930.png]]

- ### Helper Functions
	- eBPF 프로그램이 커널 기능에 접근하기 위한 안전하고 안정적인 커널 함수 집합.
		- eBPF 프로그램이 커널의 아무 함수나 직접 호출할 수 있다면, 시스템에 위협이므로 검증된 커널 함수만 호출할 수 있다.
	- 주요 헬퍼 함수
		- Map에서 키에 해당하는 값을 조회하는 함수
		- 현재 실행 중인 프로세스의 ID와 스레드 그룹 ID를 반환하는 함수
		- 커널 메모리에서 안전하게 데이터를 복사하는 함수
		- 네트워크 패킷을 복제하여 다른 인터페이스로 리다이렉션하는 함수
		- ...
![[Pasted image 20260412193218.png]]


- ### Hook
	- eBPF 프로그램이 연결돼, 실행을 시작하는 커널 내의 특정 지점 또는 이벤트
	- eBPF 프로그램은 데몬처럼 항상 실행 중이 아니다. 반드시 특정 훅에 연결되고, 해당 훅이 트리거가 돼어 실행된다.
	- #### 사전 정의된 주요 hook
		- tracepoints
			- 커널 소스 코드에 명시적으로 정의된 안정적인 추적 지점
		- XDP
			- 네트워크 드라이버 레벨의 훅
			- 가장 먼저 패킷을 만나는 지점
		- TC
			- 커널 네트워크 스택의 ingress/egress 큐에 연결
		- LSM
			- 보안 관련 커널 결정 지점에 연결
		- cgroup
			- 특정 컨트롤 그룹에 속한 모든 프로세스의 활동에 연결
	- #### 사용자가 원하는 목적에 해당하는 사전 정의된 hook이 없는 경우
		- 새로운 커널 프로브(kprobe) 또는 유저 프로브(uprobe)를 생성해서, 커널 또는 유저 애플리케이션의 거의 모든 임의의 위치에 eBPF 프로그램을 연결할 수 있다.
		- 커널 또는 유저 공간의 함수 시작/종료 지점에 유연하게 연결 가능하다.
